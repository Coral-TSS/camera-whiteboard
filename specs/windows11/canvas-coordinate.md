# 坐标系与视口定义（P2.0）

制定：2026-10-24。依据用户明确要求，用于约束 P2.1 绘图模型、P2.3 UI 到输出、P3.2 合成。

## 四条原始要求

1. 画布是独立的，不依附屏幕坐标。
2. 画布外面有一个可以关闭的窗口，尺寸可调（像一个小号浏览器窗口）。
3. 缩放影响线宽。
4. 越界的笔迹不要，只保留窗口内的。

## 修订（2026-10-24，实测反馈后）

最初的实现把画布坐标直接绑到屏幕坐标（视口原点 = 窗口在屏幕上的位置）。实际使用后用户指出：
**拖动白板窗口时，之前画的内容被留在了原地**。

因此改为**纸坐标模型**：

- 画布 = 一张纸，原点固定在纸的左上角；窗口只是这张纸在屏幕上的呈现。
- **视口原点恒为 `(0, 0)`**，`vx, vy` 不再随窗口移动而变化。
- 拖动窗口 = 把整张纸连同内容一起移动；已有笔迹坐标不变，显示位置跟着走。
- 缩放窗口 = 换一张更大/更小的纸（`vw, vh` 变化），输出帧固定 1280×960，
  因此 `s = 1280 / vw` 随之变化，线宽按 `width_canvas * s` 生效——仍然满足"缩放影响线宽"。

## 术语

- **画布 canvas**：一张纸，原点 (0,0) 在纸的左上角，单位是画布像素（逻辑像素，浮点）。
- **视口 viewport**：画布上的矩形 `(0, 0, vw, vh)`，等于纸的可见区域，也就是白板窗口的纸面部分（不含标题栏）。
- **缩放 s**：视口到输出帧的映射比例。输出固定 1280×960 时 `s = 1280 / vw`。
- **输出帧 frame**：视口映射后的位图，1280×960（与媒体源协商的尺寸一致）。
- **不透明度 o**：整个视口的不透明度，独立于单个笔画的 alpha（暂未实现）。

## 变换

```
输出帧坐标 = (画布坐标 - (vx, vy)) * s
画布坐标   = 输出帧坐标 / s + (vx, vy)
```

## 规则

| 项 | 规则 |
|---|---|
| 笔迹存储 | 画布坐标，浮点，与屏幕、窗口位置无关 |
| 线宽存储 | 画布单位，**不是**屏幕像素 |
| 已存在笔画的显示线宽 | `width_canvas * s`，改 s 立即生效（满足"缩放影响线宽"） |
| 新建笔画的线宽 | 用户选定的值按画布单位存；若 UI 上是以屏幕像素呈现，先除以 s 再存 |
| 取点 | 采样点落在纸面矩形内才入库；纸外的点**直接丢弃**，不做插值、不做裁剪 |
| 渲染 | 画纸面内全部笔画，超出的部分由窗口裁掉 |
| 窗口移动 | 视口原点不变，纸与纸上的内容一起移动；笔迹坐标与显示位置都不丢失 |
| 窗口缩放 | 换一张纸（`vw, vh` 变化，严格 4:3）；不改画布坐标与存储线宽，但 `s` 变化使显示线宽随之变化 |
| 窗口关闭 | 停止送出白板层；程序与画布内容保留，不视为退出 |
| 输出映射 | 视口等比贴入输出帧；比例不一致时留边，不拉伸变形 |
| 多显示器 | 视口跨屏时按逻辑坐标处理，按每屏 devicePixelRatio 分别换算；负坐标合法 |

## 为什么"越界丢弃"是划算的

不需要实现笔画裁剪、线段切分、多边形求交；越界点根本不入库，渲染时窗口裁一次就够。代价是窗口外画不出东西——这正是需求。

## 用例

**1. 视口内**
视口 `(0,0,1280,720)`，`s=1`。在画布 `(100,100)-(200,150)` 画一条 8 单位宽的线 → 输出帧同一位置出现 8 像素宽的线。

**2. 越界**
同一视口，从 `(1200,600)` 拖到 `(1400,700)`。`x>1280` 的部分丢弃，只保留到 1280 为止。之后再把握口移到 `(1200,600)`，`1280~1400` 那段**不会**出现，因为它从未入库。

**3. 缩放**
同一条 8 单位线，s 由 1 改为 2 → 屏幕上变成 16 像素宽，画布坐标与存储线宽不变。

**4. 关闭窗口**
关闭视口 → 虚拟摄像头不再收到白板层；P1 阶段输出故障占位帧，P3 接入物理摄像头后改为只送摄像头画面。

## 未决（实现时再定，不阻塞）

- **跨边界线段的锯齿**：按采样点判断，鼠标快速划出边界时截断处可能呈锯齿。若观感差，改为在边界插一个交点即可，工作量很小。
- **视口最小尺寸**：避免缩到 0 导致除零，建议不小于 64×64。
- **视口位置持久化**：存画布坐标还是屏幕坐标？画布坐标更稳（换显示器不丢）。
