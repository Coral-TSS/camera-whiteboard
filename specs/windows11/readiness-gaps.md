## 2. 设备名可编辑 —— 落地方式

`MFCreateVirtualCamera` 的 `friendlyName` 是**创建参数**，不是运行时可改属性。所以"可编辑"实际是：

- 名字存 `config.json`，形如 `{"clsid": "{...}", "deviceName": "白板摄像头"}`
- 启动时读配置 → 若已有旧设备先 Stop/Remove → 用当前名字 Start
- 会议软件正占用摄像头时改名，Remove 可能失败 → 提示"关闭占用程序后重试"
- 改名后会议软件看到的是"新设备"，要重新选一次——这是系统行为，不是 bug

成本很低：一个配置字段 + 一次设备重建。真正需要注意的是**别把设备名硬编码进 CLSID 或路径**。

## 3. 仍然真实的设计缺口：1 个

### 笔迹坐标系与对外视口的关系

spec 只说"对外用归一化 x/y/w/h + opacity"、"本地白板与对外白板位置独立"，没说清：

- 笔迹存在哪个坐标空间（逻辑画布 / 屏幕坐标）
- 对外视口是"画布的裁剪窗口"还是独立的一张画布
- 画到视口外的笔迹裁掉还是保留
- 调整对外大小时是缩放画布，还是改变裁剪范围（决定笔画粗细跟不跟着变）

这条决定数据模型，定错了 P3 合成要重写。跟商业与否无关，自用也一样会返工。
