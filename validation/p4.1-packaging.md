# P4.1 打包记录

执行日期：2026-10-26。

## 产物

| 项 | 值 |
|---|---|
| 入口 | `packaging/entry.py` → `ui.camera_whiteboard.app.main` |
| 配置 | `packaging/whiteboard.spec`（PyInstaller 6.22.3） |
| 可执行文件 | `packaging/dist/CameraWhiteboard/CameraWhiteboard.exe`（3.7 MB 引导器） |
| 整体体积 | **343 MB**（含 ffmpeg 87M；`cv2` 112M、`PySide6` 94M、`numpy` 27M） |
| 构建耗时 | 约 40 秒（首次 85 秒） |
| 形态 | 单目录（COLLECT）+ 控制台窗口 |

保留控制台的原因：摄像头打不开、共享帧写失败这些错误需要看得见。稳定后可改 `console=False`。

## 构建命令

```
.venv\Scripts\pyinstaller.exe packaging\whiteboard.spec --noconfirm ^
    --distpath packaging\dist --workpath packaging\build
```

注意：本机沙箱对"批量删除"有保护，重复构建时如果报 `SAFE_DELETE_BULK_CONFIRM_REQUIRED`，
先把旧目录改名（`move packaging\dist packaging\dist_old`）再构建。

## 关键修复：冻结后的共享帧路径

`publisher` 原来按源码位置推算 `.run/frames.bin`；打包后 `__file__` 指向 `_internal`，
会写到错误的地方，导致虚拟摄像头永远读不到。

改为与媒体源 DLL 一致的搜索顺序：

1. 环境变量 `CWB_FRAME_FILE`
2. 从**程序所在目录**逐级向上找到的 `.run`（打包产物在仓库内时命中仓库的 `.run`）
3. `%ProgramData%\CameraWhiteboard\frames.bin`

源码模式仍按仓库根推算。两条路径的判断逻辑现在是对称的。

## 验证

```
packaging\dist\CameraWhiteboard\CameraWhiteboard.exe --seconds 12
```

期间用读取器抓虚拟摄像头输出：

- 帧尺寸 1280×960 ✅
- 画面内容：摄像头实时画面 + 右下角白板面板（默认锚点 `br`、中等大小）✅
- 进程按 `--seconds` 正常退出，无残留 ✅

`--seconds` 是给无人值守冒烟用的参数，正常使用不需要。

## 已知限制

- 体积 259 MB。要压缩得动 `cv2`（112M），需要换掉 OpenCV 的采集实现，属 P3.3 范畴。
- 打包产物里的 UI 仍连仓库的 `.run`；如果把 exe 复制到别处，需设 `CWB_FRAME_FILE`，
  或等 P4.2 把 DLL 与共享帧都挪到固定安装目录。
- 未做数字签名（自用不需要），Windows 可能弹 SmartScreen。
