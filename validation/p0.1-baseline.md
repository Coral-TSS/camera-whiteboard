## 两条被实测推翻的判断

1. **"`MFCreateVirtualCamera` 需要提权"是错的**。开源项目 BestCam 的 README 如此声称，实测在未提权进程里 Create 与 Start 均返回 `S_OK`。仅 `AllUsers` 访问范围或 `System` 持久化才需要管理员。产品设计因此保持 plan.md 原方案：安装提权一次，日常普通用户运行。
2. **"DLL 放在 D 盘项目目录会导致 Frame Server 拒绝访问"未复现**。当前 DLL 位于 `D:\CodeWork\WhitePlank\third_party\vcamsample\x64\Release\`，`Start` 仍返回 `S_OK`。仍保留 ACL 处置方案作为备用，但不必预先搬到 `C:\ProgramData\`。

## 已知失败模式与处置

| 现象 | 原因 | 处置 |
|---|---|---|
| `regsvr32` 报 0x80070005 | 未提权，HKLM 不可写 | 以管理员身份重开终端 |
| `Start` 返回 `E_ACCESSDENIED` | DLL 所在路径对 Frame Server / Frame Server Monitor（Local Service / Local System）不可读 | 把整个 `Release` 目录复制到 `C:\ProgramData\VCamSample\`，从该路径重新 `regsvr32` |
| 设备可见但黑屏 | 媒体类型协商或帧生成问题 | 打开 ETW 追踪（provider `964d4572-adb9-4f3a-8170-fcbecec27467`） |
| 相机应用能看、Teams 远端看不到 | 上游 README 自述的已知问题 | P0 阶段不以此判定失败；先用相机应用与浏览器 ImageCapture 验证 |
