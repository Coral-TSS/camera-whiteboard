# P4.2 收尾验收

执行日期：2026-10-27。自用口径：只需要"自己的会议软件里能看到、能正常用、能干净卸掉"。

## 本次补齐的两件事

### 1. 设备名改成「摄像头1」

根因：Windows 11 虚拟摄像头的**显示名是创建方传进去的**（`MFCreateVirtualCamera` 的
friendlyName 参数），不是 DLL 里的常量。之前界面从来不创建虚拟摄像头，所以会议室里
看到的名字取决于上一次是谁把它建起来的（早期脚本默认名 → 样例名）。

现在：`app` 启动时读 `config/app.json`（`deviceName` / `mediaSourceClsid`），
创建并 `Start` 虚拟摄像头，退出时 `Stop` + `Remove`。

- 设备名：**摄像头1**
- 产品 CLSID `{2B28F238-…}` 未注册时自动退回样例 `{3CAD447D-…}`，并在托盘标注实际状态
- 托盘显示「虚拟摄像头：摄像头1」或失败原因

### 2. 注册 / 卸载脚本

| 脚本 | 作用 |
|---|---|
| `scripts/register_vcam.ps1` | 把 DLL 注册到产品 CLSID（**需管理员**） |
| `scripts/uninstall_vcam.ps1` | 删除两个 CLSID 注册项 + `.run` + `%ProgramData%\CameraWhiteboard`（**需管理员**） |

产品 CLSID 注册是可选的：不注册也能用（退回样例 CLSID），只是设备名走应用传入的名字，
CLSID 仍是样例的。

## 仍需人工确认（脚本无法代劳）

1. **重启后免配置**：重启电脑 → 直接双击 exe → 会议软件里应能看到「摄像头1」，不需要跑任何脚本。
   （关键前提：注册表项是持久的，应用自己创建摄像头。）
2. **睡眠唤醒**：合盖睡眠 → 唤醒 → 摄像头是否还在、画面是否恢复。已知 UVC 设备在
   异常掉电后可能卡在"只出黑帧"，届时用 `scripts/doctor_camera.py` 判定。
3. **卸载干净**：管理员运行 `scripts/uninstall_vcam.ps1` 后：
   - 会议软件里不再出现「摄像头1」
   - 其他真实摄像头（如内置）仍可用
   - `%ProgramData%\CameraWhiteboard` 与仓库 `.run` 已消失
4. **会议内实测**：腾讯会议选中「摄像头1」，确认看到 720p 人像 + 白板面板，
   再点托盘关画布，画面应回到纯摄像头。

## 已知限制

- 安装/卸载需要管理员（写 HKLM）。自用可接受。
- 未做数字签名，exe 首次运行可能弹 SmartScreen。
- 卸载脚本会强杀 `CameraWhiteboard` 进程；如果当时正在开会，会议侧画面会中断。


## 第二轮反馈的四个修复（2026-10-27）

| 反馈 | 根因 | 修法 |
|---|---|---|
| 开本应用时，别处摄像头流报错 | ffmpeg 打开 DShow 是**独占**的，应用常驻就一直占着 | 摄像头改为**按需占用**：画布打开才抢，关画布/关叠加立刻释放。实测释放后另一进程可正常打开（亮度 153） |
| 画面过一会彩色屏一闪 | 那是媒体源的**诊断图案**：帧停了 2 秒就回落。原因是发布定时器在开摄像头之后才启动，启动那几秒没在喂帧 | 调整初始化顺序：**先开发布器并喂空白帧**，再开虚拟摄像头和物理摄像头 |
| 画布大小手动调了，对外区域没变 | 输出面板大小此前是独立的"小/中/大"比例，与窗口无关 | 面板宽度直接由**窗口宽度 / 屏幕宽度**换算（`_sync_panel_ratio`），拖窗口即改输出；预设改为"改窗口大小" |
| 控制台必须一直开着 | PyInstaller 用 `console=True` 方便看日志 | 改 `console=False`，日志写 `.run/app.log`（`log.py`，窗口模式下 `sys.stdout` 为 None，不能直接 print） |

附带修的一个体验问题：打开摄像头原本阻塞主线程 **8 秒**（ffmpeg 枚举设备 + 启动），
启动时界面会卡住。改为后台线程打开（构造耗时 0.26s），并缓存 DirectShow 设备名，
打开耗时 8s → **2 秒**。

### 注意：关画布 = 让出摄像头

所以"关画布后看到纯摄像头画面"这个行为变了：画布关掉后不再占用物理摄像头，
会议里应切回真实摄像头（这正是"不抢占"的代价与收益）。


## 第三轮反馈（2026-10-27 下午）

| 反馈 | 处理 |
|---|---|
| 关画布后视频流就没了，等于要换视频源，绝对不行 | **改回常驻持有**：关画布只隐藏面板，输出仍是摄像头画面，会议里不用换源。另加托盘「让出摄像头（其他程序可用）」作为显式开关，默认关 |
| 画画时仍然彩色一闪 | 找到确切原因：DLL 的序号锁读到"写入中"（奇数序号）**立刻**回落诊断图案。我们每帧写 4.9MB，窗口 1~3ms，30fps 下就周期性闪现。两侧都改：① 发布器改用 `memmove` 只拷一次，窗口减半；② **DLL 改为重试 8 次（每次 1ms）再回落** |
| 缩放锚点不统一：本机以左上角为锚点，输出却是右下角 | 默认锚点由「右下」改为「左上」，面板随尺寸向右下生长，与本机窗口一致。其余锚点按"贴哪个角"语义（选右下时从右下角向左上长，这是锚点定义，不是错） |

### 需要重新构建 DLL

彩色闪的根治在媒体源 DLL 里（`MediaStream.cpp` 的重试逻辑），改完必须重建：

```
scripts\build-vcamsample.cmd
```

构建后无需重新注册 CLSID（路径没变），重启应用即可。


## 第四轮反馈（2026-10-27 15:40）

### 1) 所有锚点都"从左上角生长"

`Compositor` 引入 origin 模型：锚点只在**选中那一刻**决定面板左上角的位置，
之后改尺寸只长宽、左上角不动，与本机窗口"以左上角为锚点缩放"一致。

| 锚点 | ratio 0.3 | 0.5 | 0.7 |
|---|---|---|---|
| 左上 tl | 38,28 | 38,28 | 38,28 |
| 三分左上 t1l | 234,176 | 234,176 | 234,176 |
| 右下 br | 858,644 | 640,480（贴边） | 384,288（贴边） |

说明：靠右/靠下的锚点放大时会被画面边缘挡住（否则就画到画面外了），
所以会出现"贴边后不再向右下长"的情况。日常用**左上**最一致。

### 2) 镜像问题：管线里没有翻转（有实测数据）

用非对称图案验证（左半边一条红线、右上角一个绿点）：

| 环节 | 红（应在左） | 绿（应在右） |
|---|---|---|
| 合成器输出 | x 95~380 | x 719~749（面板中线 422） |
| **真实虚拟摄像头抓帧** | x 88~320 | x 604~628 |

两处都符合"红在左、绿在右"，且代码里搜不到任何 `scale(-1)` / flip / mirror。

结论：**输出没有镜像**。会议室里看到的左右相反，是客户端**自拍预览**的镜像行为
（2026-10-24 已有同样结论：腾讯会议预览是镜像的，远端正常）。

确认办法：用手机拍一张会议预览，或让对方截屏发回来对比——对方看到的应该和画布一致。


## 第五轮反馈（2026-10-27 15:50）

### 1) 画布镜像（设置项，默认开）

`Compositor.set_mirror()`：笔迹图层水平翻转后再贴到面板上，**面板位置不变**。
菜单里「镜像画布（对面看到的与手上一致）」可随时开关。

实测（左红右绿的图案）：镜像关 → 红在左 124~552、绿在右 1056~1104；
镜像开 → 红移到右 676~1104、绿移到左 120~168。

> 需要注意的风险：如果会议软件只是**自拍预览**镜像、发出去的流本身不镜像，
> 那么打开这个开关后，对面看到的字就是反的。判断依据必须是**对面屏幕上的画面**
> （让对方截屏 / 手机拍对方屏幕），不能只看自己的预览。

### 2) 画布设置搬进窗口菜单

去掉了顶部悬浮工具栏（`toolbar.py` 已删除，色板常量移到 `palette.py`）。
所有画布相关设置都在白板窗口标题栏右侧的「菜单 ☰」里：

画笔（画笔/橡皮、颜色、笔宽）· 撤销 · 清空 · 画布位置（13 锚点）· 画布大小 ·
镜像画布 · 叠加摄像头画面 · 让出摄像头 · 输出白底 · 穿透 · 关闭画布

托盘菜单保留（画布关掉后还能从托盘打开）。

### 3) 不再永远置顶

`WindowStaysOnTopHint` 已移除：切到其他应用时白板会正常退到后面。


### 6) 镜像时方位不再跟着翻（2026-10-27 16:10）

之前镜像只翻笔迹内容，用户选的方位在（被镜像的）预览里会左右对调：选「左上」看到的是右上。

现在 `layout.mirrored_anchor()`：开镜像时按**反向锚点**落位（左上↔右上、左中↔右中、
三分左↔三分右，中/上中/下中不变），于是镜像视图里看到的方位就是用户选的那个。

实测（选左上、镜像开）：面板落在输出 x=602（右半），镜像后看回去正好在左半。

代价说明：如果哪天关掉镜像，方位会回到原始锚点，两者始终一一对应。


### 7) 启动更快 + 边距加大（2026-10-27 16:20）

**「要过好一会才选到摄像头1」**：实测打包版从双击到虚拟摄像头就绪 **5.74 秒**，
时间几乎全花在 PyInstaller 解包 + 导入 Qt/opencv 上，而虚拟摄像头是在界面之后才建的。

改法：把"建虚拟摄像头"提到**任何重依赖导入之前**（新的 `bootstrap.py` + `paths.py`，
只用标准库 + ctypes），界面加载完再把这个实例交给 UI 复用。

实测：**5.74s → 0.62s**。（第二次测得 0.00s 是脚本读到上一轮日志的假象，不计。）

**「选右上被挡住一部分」**：先确认了面板坐标从不越界（13 锚点 × 4 档尺寸 × 镜像开关
全量检查，无越界）。判断是贴边余量太小（3%），而会议客户端常把 4:3 裁成 16:9 显示，
边缘内容会被切掉。

改法：`MARGIN_RATIO` 3% → **6%**（1280 宽下约 77 px）。


### 8) 撤回锚点镜像 + 安全区（2026-10-27 16:28）

上一轮把"镜像也翻锚点"理解错了，实际要求是**位置严格按用户选的锚点**，与镜像无关。
已撤回 `mirrored_anchor`：镜像只翻笔迹内容，位置一动不动（测试断言 `set_mirror` 前后
`panel_rect()` 完全相等）。

顶部被切的问题：判断是会议客户端把 4:3 画面**裁边显示**（上/三分上时面板上沿正好在被
裁掉的带子里）。改法：

- `MARGIN_RATIO` 3% → **14%**（1280x960 下左右 179px、上下 134px）
- 所有锚点结果都**夹进安全区**，原来"三分上"落在 y=128（高于安全线）现在被抬到 134

新增校准开关：菜单 →「显示安全区边框（校准用）」，会在输出上画一圈品红边框，
在会议里一看就知道客户端裁掉了多少，看完关掉即可。
