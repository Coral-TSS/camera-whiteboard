# P0.3 动态收流记录

执行日期：2026-10-24。

## 工具

`scripts/read_vcam.py`：自建 Session 级虚拟摄像头 → `Start` → `GetMediaSource` → `IMFSourceReader`
连续取帧，统计帧数、时间戳单调性、画面内容变化与实际帧率，结束时 `Remove`。

不依赖设备枚举（`MFEnumDeviceSources` 在本机返回 `E_INVALIDARG`，原因未明；本路径改为直接
从自己创建的摄像头取媒体源，规避该问题）。

## 基线构建结果（改动前）

命令：`.venv\Scripts\python.exe scripts\read_vcam.py --frames 300 --timeout 40`

| 指标 | 结果 |
|---|---|
| 帧数 | 300 |
| 实测帧率 | 65.43 fps |
| 不同画面数 | 300（每帧都不同） |
| 时间戳单调 | 是（0 次倒退或重复） |
| 平均帧间隔 | 15.18 ms |
| `Remove` | `0x00000000` |
| 判定 | **通过** |

补充观察：

- 媒体源默认输出子类型为 `0x00000016`（RGB32）。请求 NV12 时 `SetCurrentMediaType` 返回
  `0xC00D5212`，可能是未在请求中给出 `MF_MT_FRAME_SIZE` 所致；当前不影响验收。
- 本路径下帧率为 65 fps，说明媒体源不做节流，节流由 Frame Server / 消费者驱动。720p30 的
  持续性能要在 P3.2 通过真实客户端链路测，不能用本数字替代。
